# Word Frequency —— Zotero 英文文献词频统计插件

在 Zotero 右侧的**条目窗格**里加一个「词频」区块：选中带 PDF 的文献，点区块里的按钮，
统计这篇文献的整本词频，把结果写成 CSV 放到 PDF 同目录；遇到非英文文献直接拒绝并说明依据。

- 插件 ID：`wordfreq@klskz.local`
- 版本：2.5.0
- 目标环境：Zotero 10.0.6（`strict_max_version` 写到 10.9.9）
- 输出格式：CSV（UTF-8 带 BOM，CRLF 换行）

> **版本说明**
> 1.0.0 的菜单挂不上；1.0.1 改用官方 `MenuManager` 后菜单能出现，**但会让右键菜单本身弹不出来**；
> 1.1.0 撤掉右键菜单，改成右侧条目窗格里的区块；
> 2.0.0 加上词形归并（dogs 并进 dog，am/is/are 并进 be）；
> 2.1.0 给窗格词表加上筛选与分页；
> 2.2.0 加上用户自定义名单；
> 2.3.0 不再自动弹文件夹、行内按钮缩小、名单改为弹窗、去掉常用词与简单词筛选；
> 2.4.0 已有词频表的文献直接显示结果，按钮改为「更新词频」并加二次确认；
> 2.5.0 窗格只留词表本身，去掉统计信息行、序号与合并明细，每页改为 20 个词。
> 装法都一样，用「Install Plugin From File…」覆盖即可。

12. 带 `forms` 列的新 CSV 在 Excel 里能否正常打开（引号包起来的字段里有分号）。

## 二、安装

Zotero 运行期间插件文件被锁住，塞进配置目录也装不上；Zotero 默认还关掉了对 `extensions/`
目录的启动扫描。所以安装只能在界面里点：

1. 打开 Zotero
2. **工具 → 插件**
3. 右上角齿轮 → **Install Plugin From File…**
4. 选 `dist/zotero-wordfreq-1.1.0.xpi`
5. 按提示重启 Zotero

装之前可以先跑一遍校验，确认包本身没问题：

```powershell
node scripts/install.mjs
```

它会解开 XPI 逐条检查清单字段和文件清单，并打印本机 Zotero 版本、配置目录、
以及这个插件之前装没装过。

## 三、怎么调用

**入口一：右侧条目窗格里的「词频」区块。**

在文献列表里选中一个条目（或它的 PDF 附件），右侧条目窗格往下拉，找到**「词频」**区块：

```
词频
├─ [更新词频]  [打开 CSV]        ← 已经有表时按钮变成这个
├─ [−] the                6,256
├─ [−] of                 4,243
├─ [−] and                2,140
├─ [−] in                 2,056
│  …
├─ [上一页] 第 1 / 412 页　共 8,234 个词元  [下一页]
├─ ☑ 隐藏自定义单词
├─ [自定义名单（2 个）]      ← 点开是单独的弹窗
└─ CSV：C:\...\paper_wordfreq.csv
```

窗格里只有词表。统计数字、取文本方式、词形合并明细都不显示，需要那些信息看 CSV。

- 每个词左边的 **−** 按钮把这个词加进自定义名单；已经在名单里的词，按钮会变淡。
- 「自定义名单」按钮弹出单独的面板，里面列出名单里的词，逐条移除，也能一键清空、分页浏览。
- 选中的条目没有 PDF 时，区块仍然显示，正文里写明原因，按钮置灰。
- 统计完成后**不会**自动弹出文件夹。要看结果点「打开 CSV」，它在资源管理器里定位到文件。
- 同一个条目统计过之后，切走再切回来还能看到上次的结果，但页码会回到第一页。
- 侧栏（sidenav）里也有一个「词频」按钮，可以快速跳到这个区块。

**筛选只作用于窗格里显示的这份列表，CSV 始终是完整的。** 表里哪一个词都不能少，
不然数据记录就不成立了。

### 已经有词频表时不再要求你重算

选中一篇统计过的文献，窗格**直接显示上次的结果**，不用再点按钮。判据是 PDF 同目录下
有没有对应的 CSV：先试默认文件名 `<名>_wordfreq.csv`，没有再扫目录里带序号的版本
（设置里关掉覆盖时会写成 `_2`、`_3`），取序号最大的那个。

数据是从 CSV 里读回来的，不重新提取 PDF 全文。这样做有两个好处：快，而且显示的就是
磁盘上那份表的真实内容。读回来的结果和重新算出来的走同一套筛选与分页，界面上没有区别。

这种情况下按钮变成 **「更新词频」**，点它会先弹一个确认框：

```
这篇文献已经有词频表了：C:\...\paper_wordfreq.csv

重新统计会覆盖它，词频和词元数都会重新算一遍。要继续吗？
```

确认之后才重算。想换设置（比如改词形归并）再算一遍时，走的就是这条路。

表格超过一页时，读回来的行和重新算出来的行走的是同一套分页与筛选逻辑，没有区别。

**入口二：工具 → 统计词频（英文）…**，对当前选中的条目跑，可以一次处理多个。
这一条不受条目窗格的显隐影响。

**入口三（不用界面）：** 菜单「工具 → 开发者 → 运行 JavaScript」，粘贴：

```js
Zotero.WordFreq.run(Zotero.getActiveZoteroPane().getSelectedItems())
```

**如果窗格区块没出现，先跑这个自检：**

```js
Zotero.WordFreq.debugUI()
```

它会报告 `ItemPaneManager` 是否可用、区块的 paneID 注册成了什么、
每个主窗口里能不能找到区块元素、以及当前选中的条目能不能找到 PDF。
把结果发我就能定位。

### 自定义名单

词表每行左边的 **−** 把词加进名单。名单是**全局**的：在 A 文献里加了 `deleuze`，
之后读 B、C 文献也不再显示它，不用一本一本重设。

**管理入口是窗格底部那个「自定义名单（N 个）」按钮**，点开是一个单独的面板：

```
自定义名单（37 个）                        [清空] [✕]
  deleuze                                  [✕]
  kittler                                  [✕]
  …
  [上一页]  第 1 / 4 页  [下一页]
```

面板里的列表按「每页显示多少个词」分页，和窗格词表共用同一个设置。

名单存在设置项 `extensions.zotero.wordfreq.userHiddenWords` 里，是一段 JSON 数组，
跟着 Zotero 的设置一起持久化。词按小写存储，`Deleuze` 与 `deleuze` 算同一个。
设置项被人手改坏时按空名单处理，不会让面板挂掉。

如果名单里的词被藏起来、你在词表里点不到它了，去这个面板里收拾，或者先关掉
「隐藏自定义单词」勾选框让它重新出现。

### 为什么不用右键菜单

1.0.1 把菜单项挂在文库右键菜单上（`MenuManager` 的 `main/library/item`）。
结果是**右键菜单本身经常弹不出来**，关掉插件就正常。这条路整个撤掉了。

另外 Zotero 对 `main/library/item` 有「收纳」机制：弹菜单前算一次
「屏幕上还平铺得下几个插件菜单项」，放不下就把插件项塞进底部的
**「更多选项…」**（`menu-custom-group-submenu`）子菜单。所以就算不崩，
它在右键菜单里也会时有时无。条目窗格没有这个问题。

### 为什么不用工具栏

工具栏按钮要往 `#zotero-toolbar` 里注入 DOM，而插件的 `startup` 跑在
主窗口打开之前（`Zotero.Plugins.init()` 在主窗口之前被 await），
那一刻拿不到窗口。条目窗格走的是 Zotero 自己的注册接口，窗口生命周期由它管，
不碰 DOM，也就绕开了这个时序坑。

## 四、输出长什么样

`docs/sample-output/english-medium_wordfreq.csv` 是真实语料跑出来的，开头几行：

```csv
# 来源文件,english-medium.pdf
# 生成时间,2026-10-16 21:14:08
# 全文词次,10160
# 表中词次,10160
# 去重词数,1998
# 词形归并,已开启，303 个词条由多个词形合并而来
# 语言判定,英语功能词命中率 37.2%，是次高语言（荷兰语 7.1%）的 5.20 倍。
# 取文本方式,取自 Zotero 全文缓存
rank,word,count,share_percent,forms
1,the,530,5.2165,
2,and,421,4.1437,
3,of,352,3.4646,
4,a,226,2.2244,
5,be,218,2.1457,is:90; are:47; be:37; was:22; were:14; been:7; being:1
6,in,205,2.0177,
7,to,127,1.2500,
8,as,104,1.0236,
9,synthesizer,104,1.0236,synthesizer:57; synthesizers:44; synthesizer's:3
```

前 8 行是 `#` 开头的元信息，记录这份表是哪来的，日后回头核对用。之后是表头和数据。

- `rank`：按次数降序的序号，次数相同时按字母升序，保证每次跑出来顺序一致。
- `word`：词元（原形）。开了词形归并时，这里是归并后的形式。
- `count`：该词元在全文出现的次数。
- `share_percent`：占全文总词次的百分比，保留 4 位。
- `forms`：这个词元由哪些词形合并而来。只有一个词形时留空。
  含分号与冒号的字段会被双引号包起来，Excel 与 pandas 都能正确解析。

Excel 双击即可打开（UTF-8 BOM 让 Excel 正确识别编码）。用 pandas 读：

```python
import pandas as pd
df = pd.read_csv("english-medium_wordfreq.csv", comment="#")
```

文件写在 PDF 的同目录下，文件名是 `<PDF 名>_wordfreq.csv`。
存储型附件就是 Zotero 的 `storage/<附件 key>/` 目录，链接型附件就是你自己的那个文件夹。

`docs/sample-output/` 下还有三份真实产出，以及 `chinese.rejected.txt` ——
中文文献被拒绝时插件给出的理由原文。

## 六、语言判定是怎么做的

三层证据，任何一层判定为非英文就拒绝，并把依据写进提示。

**第一层：书写系统。** 统计所有 Unicode 字母里非拉丁字母的占比。非拉丁字母超过 2%
直接拒绝。中文、日文、韩文、俄文、希腊文、阿拉伯文在这一层被拦下。
实测你库里的中文文献这一项是 100.0%。

**第二层：变音符密度。** 拉丁字母里带变音符的（é ü ñ ç ø å）占比。英文正文通常
在 0.5% 以下，你库里三份英文文献实测是 0.00% / 0.05% / 0.07%。这一层只作旁证，
不单独定案——PDF 提取会丢符号，参考文献里的人名会抬高它。

**第三层：功能词命中率（决定性的）。** 取正文中段的一批 token（跳过开头 2000 字符，
避开标题、作者、单位），统计落在各语言高频虚词表里的比例。七套表：英、法、德、西、意、葡、荷。
两条同时满足才判英文：

- 英语命中率 ≥ 20%
- 英语命中率 ≥ 1.3 × 次高语言

实测英语文献的命中率是 37%–46%，次高的是荷兰语（共用不少虚词），倍数 4.5–9.0。
门槛留了很大余量。中文因为一个拉丁词都切不出来，在书写系统那一层就返回了。

三种特殊情况单独报，不混进「非英文」：

- 样本少于 300 个词：「正文里可用的词只有 N 个，少于判定的下限」
- 没有文字层（扫描件、乐谱）：「若这是扫描件，请先做 OCR」
- 纯非拉丁文本：「检出中日韩文字占全部字母的 100.0%」

判定顺序上有过一个真 bug：原先把「词数够不够」放在书写系统前面，
中文正文切不出拉丁词，于是被误报成「文本太短」而不是「非英文」。已修。

## 七、一个必须知道的事实：全文缓存默认只有前 100 页

Zotero 建全文索引时调的是 `PDFWorker.getFullText(itemID, fulltext.pdfMaxPages)`，
`pdfMaxPages` 的默认值是 **100**。超过 100 页的 PDF，`.zotero-ft-cache` 里
根本没有后面的页，而它读起来仍然是一份完整文本。

在你自己的库里这个坑是真实存在的，我查了 `zotero.sqlite` 的 `fulltextItems` 表，
70 条记录里有 11 条 `indexedPages < totalPages`，最夸张的一条是 1121 页的书只索引了 100 页。

所以插件的「取文本方式」默认是**自动**：先看 `getPages()` 返回的已索引页数和总页数，
覆盖不完整就改用 `getFullText(id, null)` 现场提取全部页。这条路慢一些，
但统计的才是整本书。设置里可以强制只用缓存或总是现场提取。

## 八、词频口径

| 项 | 默认 | 说明 |
|---|---|---|
| 大小写 | 合并 | `The` 与 `the` 算同一个词 |
| 变音符 | 折叠 | `naïve` → `naive`，`café` → `cafe`。不折叠的话 `[a-z]+` 会把它切成 `na` 和 `ve` 两个假词 |
| 连字符 | 拆词 | `well-known` 记作 `well` 与 `known` |
| 行末断词 | 还原 | `informa-` 换行接 `tion` 记作 `information` |
| 连字 | 还原 | `ﬁ ﬂ ﬀ ﬃ ﬄ` 拆回 `fi fl ff ffi ffl`（NFKC） |
| 撇号 | 统一并保留 | `it’s` → `it's`，算一个 token |
| 破折号 | 当分隔符 | `one—two` 记作 `one` 与 `two` |
| 数字 | 排除 | 不算单词 |
| 屈折变化 | 合并 | `dogs` → `dog`，`am/is/are` → `be`。详见下一节 |
| 派生变化 | 不合并 | `happiness` / `national` / `quickly` 各算各的 |
| 停用词 | 不过滤 | 默认输出全部单词，`the`、`of` 都在表里 |

**已知的取舍**：行末断词还原是无条件的，所以 `well-` 换行接 `known` 会被并成
`wellknown`。这是同类工具的通行做法，代价是极少数真正的复合词会被并错。
不想要可以在设置里关掉。

## 九、词形归并（lemmatization）

`dogs` 与 `dog` 合并，`am / is / are / was / were / been / being` 合并成 `be`，
`walk / walks / walked / walking` 合并成 `walk`。默认开启，设置里可以关。

**只并屈折变化，不并派生。** 单复数、动词时态、不规则形式属于同一个词的变形，合并合理；
`happy / happiness`、`nation / national`、`quick / quickly` 换了词性或词义，合并会掩盖信息，
一律不动。

### 怎么做的

三条路一起用，都不依赖第三方库：

1. **不规则表**：`am→be`、`went→go`、`children→child`、`better→good`。规则推不出来的都在这里。
2. **后缀规则**：`-s` / `-es` / `-ies` / `-ed` / `-ing`，配合两张保护表：
   - 禁剥表：长得像屈折变化其实不是的词，`news`、`physics`、`during`、`unexpected`；
   - 已知原形表：`like`、`use`、`create`、`compel` 这类，用来在多个候选之间挑对原形。
3. **文档词汇表**：同一份文献里出现过的词形。`used` 该归 `us` 还是 `use`？
   文献里出现过 `use` 就选 `use`。

### 几个具体的判定

| 输入 | 输出 | 靠什么 |
|---|---|---|
| `am` `is` `are` `was` `were` `been` `being` | `be` | 不规则表 |
| `dogs` | `dog` | `-s` 规则 |
| `boxes` `churches` | `box` `church` | `-es` 规则 |
| `roses` `houses` | `rose` `house` | `-ses` 结尾回到 `-se` |
| `studied` | `study` | `-ied` → `y` |
| `stopped` `running` | `stop` `run` | 双写还原 |
| `pulled` `buzzed` `drilled` | 不变 | `ll` / `zz` / `ll` 本身就是合法词尾，不还原 |
| `liked` `used` `making` | `like` `use` `make` | 已知原形表 |
| `dog's` `it's` | `dog` `it` | 所有格与缩写合并 |
| `Sachs` `Gilles` `Charles` | 不变 | 专有名词不做规则剥后缀 |
| `unchanged` `unnoticed` | 不变 | `un-` 加过去分词构成的形容词 |
| `unfolded` `unleashed` | `unfold` `unleash` | `un-` 开头但本身是动词 |

### 不合并的几类

- **派生词**：`happiness`、`national`、`quickly`。
- **规则的比较级**：`bigger`、`happier` 不并进 `big`、`happy`。学术文本里 `-er` 绝大多数是
  施事名词（`computer`、`reader`、`user`），按规则剥会剥出 `comput` 这种垃圾。
  不规则的照并：`better/best → good`，`worse/worst → bad`。
- **原形有歧义的**：`more` / `most` 同时是 `much` 和 `many` 的比较级，`less` / `least` 同时是
  `little` 的，`further` 在学术文本里常当「进而」用——这些都不并。
- **情态动词照并**：`could→can`、`would→will`、`should→shall`、`might→may`。
  这是语料库语言学的通行做法，但你要是觉得别扭，我可以关掉这一组。

### 效果与已知误差

三份真实语料的实测：

| 语料 | 词形去重 | 词元去重 | 减少 |
|---|---|---|---|
| 短英文（20 KB） | 955 | 809 | 15.3% |
| 中英文（72 KB） | 2384 | 1998 | 16.2% |
| 长英文（600 KB，整本书） | 10231 | 8243 | 19.4% |

长语料的高频词排序在归并后的变化：`be(1856)` 从第 5 位冒出来，`instrument(757)`
取代了原来的 `instruments` 与 `instrument` 两条。

归并靠规则，一定有错。已经处理掉的主要是两类：**专有名词被剥后缀**（`Sachs→sach`）和
**`-e` 结尾动词缺原形**（`invoked→invok`）。剩下的零星误差来自 PDF 提取时丢掉的连字符
（`machine-generated` 被提取成 `machinegenerated`），数量很少。

`node scripts/lemma-audit.mjs` 会把归并结果摊开，列出「纯靠规则推出的词元」，
其中不是英文词的就是切错的。补 `lemma.js` 里的原形表就能收敛。

## 十一、开发与自测

```powershell
node scripts/check.mjs        # 静态检查：语法、文案 id、设置项键名对齐、XHTML 良构
node scripts/selftest.mjs     # 离线自测：181 项，含真实语料的判定数值与 CSV 往返
node scripts/lemma-audit.mjs  # 归并审查：把切出来的词元摊开，找非词
node scripts/demo.mjs         # 端到端仿真：拿真实语料产出 CSV 到 docs/sample-output/
node scripts/build.mjs        # 打包 XPI
node scripts/install.mjs      # 校验 XPI 并打印安装步骤
```

静态检查里有几项是专门挡「装上去什么都不显示」这类问题的：脚本引用的 ftl 文案 id
是否都有定义、`preferences.xhtml` 里 `preference=` 绑定的键是否都在 `prefs.js` 有默认值、
代码里 `prefGet()` 读的键是否都存在、`bootstrap.js` 的脚本列表与实际文件是否对得上。

离线自测把纯逻辑脚本整体加载进 `node:vm` 沙箱跑。`pane.js` 只在函数体内引用 Zotero，
所以也能进沙箱做一次加载检查。
